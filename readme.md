# RPGForge

## About

The RPGForge project is an **experimental C++ framework** that provides many typical RPG game systems to make RPG development easier and faster.

First of all, this is a personal project, so I have no intention of convincing you to use it. However, I would really appreciate your feedback, both to improve the program and, honestly, for my own personal satisfaction.

### Inspired by Tabletop RPGs

RPGForge's main inspiration comes from tabletop RPGs such as Dungeons & Dragons. This means that the focus is on role-playing and creating a story, not just playing a game (although it is a game too).

There will be many mechanics and guides to encourage users to give more depth to their stories. However, the final decision will always be up to the user.

### Sample Campaigns

Throughout the development of the project, I will also create sample campaigns (mostly medieval fantasy) so users can test the tool's results and see examples of it in practice.

### Origin

The idea for this project came a long time ago, when I started programming and consequently started using the terminal. I remember having this "vibe" — I don't know exactly where it came from — of text-based RPGs running in the terminal. I have always found this aesthetic interesting.

Now that I am learning C++, I want to use this project as a tool to further develop my programming skills.

# FAQ

### 1. What is a "Campaign"?

As the main inspiration for this project is TTRPGs, we will use the term "Campaign" for adventures and worlds created using RPGForge.

Each Campaign can have its own characters, NPCs, dialogues, locations, dungeons, quests, rules, and story. This allows different RPGs to be built and played using the same RPGForge.

### 2. How do I create a Campaign?

As of now (v0.1), campaigns aren't even a thing yet, so you can only test some features — you can't even play the game.

In v0.2, there will be some functions that will make things easier.

Technically speaking, what I currently expect is that a Campaign will be a `.cpp` file containing the code that runs the campaign. The systems will be separated into another folder and will provide functions that can be used by the Campaign.

As time passes, the framework's usage will become better explained and more clearly defined. Maybe I can even create a visual Campaign Creator someday.

### 3. Who is RPGForge intended for?

Anyone who wants to create an RPG adventure, especially TTRPG enthusiasts.

However, the framework is not too hard to learn, even for beginners. If something is too difficult, it probably means it could be improved, so feel free to give me feedback!

### 4. What does RPGForge actually provide as a framework?

It provides functions that make RPG development easier, allowing users to focus more on the story instead of the coding.

However, I must clarify that coding is not excluded from the process at all.

### 5. What is the difference between RPGForge, a Campaign, and a Player?

RPGForge is the framework. Campaigns are files that use it to create one or multiple storylines, and Players are the people who play the `.exe` product.

In other words:

**RPGForge (mechanical framework) → Campaign (uses the framework to create storylines) → `.exe` (final game product)**

### 6. How much freedom does the user have with a Campaign?

With the Campaign file, you can change the default ability scores (for example, instead of Strength, Dexterity, Intelligence, etc., you could use Physical and Mind), create new classes, and make many other rule changes.

When you need to change more parameters, you can always access the framework files and edit them.

This means you can use RPGForge for any theme and adapt many of its features to match the setting.

### 7. What's the difference between a Tool User and a Player?

The Tool User will create and edit the Campaign file, possibly even editing the framework in the process, and will actively work with the RPGForge framework.

The Player is expected to only receive the `.exe` file that runs the Campaign.
